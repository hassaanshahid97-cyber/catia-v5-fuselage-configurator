================================================================================
ROOT CAUSE
================================================================================

The error occurred when calling AddSectionToLoft() with a third parameter
set to "Nothing":

    WRONG:
    oLoft.AddSectionToLoft(refBhk(0), 1, Nothing)

In VB.NET COM interop, the third parameter is OPTIONAL. When you try to pass:
  - Nothing → causes Type Mismatch (0x80020005)
  - System.Reflection.Missing.Value → causes Parameter not optional (0x8002000F)

CATIA's AddSectionToLoft signature:
  AddSectionToLoft(section As Reference, orientation As Integer, _
                   [closingPoint As Optional])

The third parameter is the closing/coupling curve, which we don't need.
The correct VB.NET approach: simply OMIT it.

================================================================================
THE VB.NET WAY FOR COM OPTIONAL PARAMETERS
================================================================================

In VB.NET, when a COM method has optional parameters, you have two choices:

1. PROVIDE ALL PARAMETERS (harder in .NET):
   - Cannot use Nothing
   - Cannot use System.Reflection.Missing.Value (causes "Parameter not optional")
   - Must use the correct type/value

2. OMIT OPTIONAL PARAMETERS (simplest - what we do):
   - Just don't pass them
   - VB.NET handles it automatically
   - Works perfectly with CATIA COM

================================================================================
KEY LESSON: VB.NET vs VBScript COM Interop
================================================================================

VBScript macro (works with Nothing):
    oLoft.AddSectionToLoft refBhk(0), 1, Nothing
    oLoft.AddSectionToLoft refBhk(0), 1  ' same - omit optional

VB.NET code (MUST omit optional parameters):
    oLoft.AddSectionToLoft(refBhk(0), 1)  ' ONLY this way works


VB.NET does NOT support passing Nothing to omitted optional parameters
in COM. You must use one of:
  1. Omit the parameter (BEST - what we do)
  2. Provide a proper value for the parameter (harder)
  3. Use wrapper functions (overkill)
